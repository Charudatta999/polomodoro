The derived accent palette

03

Auto is the default. When backgroundSource is spotify the palette is derived from the current album cover; otherwise from the active wallpaper. A manual override in Settings pins one accent and freezes derivation.

Five swatches come out of every image. Extraction runs on a downscaled 64×64 copy, k-means over OKLCH, then each role is clamped into a readable band before it reaches QML. A cover that is entirely black or entirely pastel still yields a usable accent.

Clamp · lightness
OKLCH L held to 0.62–0.82. Guarantees ≥4.6:1 against bgBase for the 13 px accent label, the smallest accent-coloured text in the app.
Clamp · chroma
C held to 0.09–0.22. Below that a greyscale cover produces an accent indistinguishable from muted; above it, banding on the ring gradient.
Derivation rules
break = accent hue −38°, overflow = nearest hue to 85° (amber) so over-target always reads as warning, muted = accent at C 0.03, L 0.55.

Geometry
Diameter — height × 0.45, clamped 168–280 px so the dial scales with a manual resize but never dominates.
Stroke — diameter × 0.046, floor 6 px. Proportional stroke keeps the ring reading the same at every size.
Start angle — 12 o'clock, clockwise. Rotation −90° applied to the Canvas, not the arc maths.
Direction — Pomodoro depletes; stopwatch fills from zero and wraps hourly with a tick count in the eyebrow.
States
Running
Arc accent at full opacity, eyebrow shows phase name, digits 100%.
Paused
Arc drops to muted, digits to 62% opacity, eyebrow reads PAUSED. No animation — stillness is the signal.
Break
Arc, eyebrow, cycle dots and page tint all swap to break together over 420 ms.
Idle
Full trough, no arc, digits show the configured work length. Start button is the only accent on screen.
Overrun
Stopwatch past 60 min: arc continues in overflow over the accent ring, digits gain an h group.
QML implementation
Draw the ring with a Shape + ShapePath + PathAngleArc, not Canvas — Shape renders on the scene graph and costs nothing per tick, whereas a Canvas repaint at 10 Hz shows up in QSG_RENDER_TIMING.

Bind sweepAngle: 360 * TimerController.progress. Keep progress a single qreal property on the controller; emitting it alongside remainingMs avoids a second binding pass.

Digits are three separate Text items (minutes, colon, seconds) in a Row, so the tick animation can target the seconds only. The colon has fixed width to stop the group shifting.

The whole dial is one MouseArea: click toggles start/pause. Full file at qml/components/TimerDial.qml.

Rows without a target show a full-width muted bar and elapsed only — a grey full bar reads as "tracked, ungoverned" rather than "complete".
Overall ratio
overallRatio = Σ progressMs / Σ targetMs
  over active tasks + descendants
  where targetMs != null  → clamp 0…1
Summing milliseconds rather than averaging ratios is deliberate: a 4-hour task should dominate a 5-minute one. If no active task has a target the bar falls back to a pulsing neutral fill with a combined elapsed label instead of a percentage.
States
Tracking
Accent fill, percentage label, 320 ms OutCubic on every ratio change.
No targets
Neutral fill pulsing 0.35 ↔ 0.6 α over 2.4 s; label shows 1h 12m active.
Nothing active

Over target
Fill reaches 100% then the last segment renders in overflow; label gains +15m.
Hover
Trough lightens to #22262E, chevron appears — the only affordance that the bar is clickable.
QML implementation
Animate window.height, not a clipped inner Item — a frameless always-on-top bar must not leave a transparent dead zone over other windows. Drive it with a Behavior on height and recompute contentHeight from the filtered model's count.

The dropdown list is the same TaskTreeModel behind a proxy filtered to the active subtree — do not build a parallel list, or the two views drift.

Depth > 3 is flattened with a … prefix rather than indented further: at 520 px the title column disappears otherwise.

Block vocabulary
Planned — dashed 1 px outline, no fill, from scheduled_start_at → scheduled_end_at. Hollow because nothing has happened yet.
Logged — solid accent, one block per sessions row. Contiguous sessions under 2 min apart are merged so a pomodoro cycle reads as one bar.
Over target — the portion of a logged block past target_ms renders in overflow.
In progress — hatched, open-ended, grows with the clock. Has no bottom edge because it has no end yet.
Now line — 1 px accent rule with a dot and a mono label, repositioned every 60 s.
Layout rules
Scale
Fixed 72 px per hour. Not fit-to-height — a 14-hour day would compress a 12-minute session below its own label.
Window
Opens scrolled to 1 h before the first block of the day, or to the now line if today.
Overlaps
Concurrent blocks split the column width evenly, max 3 lanes; beyond that the narrowest collapses to a 4 px accent tick.
Min height
18 px. A 3-minute session still needs to be clickable.
Labels
Dropped below 34 px of block height; the tooltip carries the title and duration instead.
QML implementation
One Flickable containing an Item of height 24 * 72, with Repeaters for hour rules, planned blocks and logged blocks. Absolute y from a single msToY() helper — do not lay blocks out with a Column.

Blocks come from a dedicated DayTimelineModel that queries sessions by date range, not from TaskTreeModel — the tree has no notion of when time was spent.

Keep the day strip to seven fixed columns; a month view is out of scope and the strip should not imply one.

The now line and the in-progress block share one 60 s timer with the Future→Pending promotion tick. Full file at qml/components/DayTimeline.qml.

Art → background → accent
The cover is the background (blurred, FastBlur 40) and the palette source. One image drives both, so the frosted panels always sit in a colour family the accent belongs to. Track change: 1.2 s image crossfade, 420 ms accent animation — the colour arrives a beat before the picture settles.
Drawer behaviour
340 px, pushes the timer panel (unlike the task drawer, which overlays) — music is a companion, not a modal task. Collapsed it becomes a 34 px edge tab. Ctrl+M toggles. The WebEngineView is never unloaded, only hidden: art, metadata and transport all keep working in bar and PiP modes.
Fallback chain
Nothing playing → last known art, still blurred. No art ever seen → blurred gradient from the last derived palette. Not logged in, or spotifyArtFallbackToWallpaper true → revert to wallpaper and re-derive. The app never shows an empty background or a spinner behind the timer.
QML notes
Give the WebEngineProfile a fixed storageName and AllowPersistentCookies, or the user re-authenticates every launch.

Poll navigator.mediaSession.metadata every 2 s via runJavaScript; fall back to the now-playing bar img selector. Treat both as fragile and log selector misses rather than failing loudly.

Palette derivation must not run on the GUI thread — grab the art via QNetworkAccessManager, downscale and k-means in a worker, emit the five colours as one struct.

Playback needs Premium; the drawer shows an inline notice rather than a broken player when the web app refuses.

Shared rules
Both compact modes are frameless, draggable by their background, and auto-pin on entry (barAutoAlwaysOnTop / pipAutoAlwaysOnTop), restoring the previous pin state on exit. Each mode keeps its own geometry key, so switching back always lands where you left it.
PiP target rule
The slim bar appears only when exactly one active task has a target. Two or more and it shows the count instead — a bar that silently represents an aggregate at this size is worse than no bar.
QML notes
WindowLayoutManager owns viewMode and all three geometry keys; QML reads, never writes, geometry directly.

Bind flags reactively for the frameless + stay-on-top combination, and re-apply after a mode change — on some Wayland compositors changing flags recreates the surface and drops the hint.

Use a StackLayout keyed on viewMode with all three views instantiated: rebuilding the expanded view on every return costs ~120 ms and the WebEngineView must not be reparented.

Drag via DragHandler on the background only, with startSystemMove() where available.

One icon, one title, one line of detail, at most two actions. Icon background carries the semantic colour — accent for success, overflow for warnings, break for phase changes. Actions are omitted entirely on desktops whose notification daemon ignores them.
Over-target & overdue
Crossing 1.0
Fill switches to overflow for the segment past target, one 1.04 scale pulse, and target_reached_at is stamped. Never fires twice, even after a restart.
Label
2h 15m / 2h 00m (+15m) — the overflow is stated explicitly rather than implied by a bar that cannot exceed full.
Overdue
Row border and a badge line in #E8489B: Overdue by 2h. Distinct from over-target — one is a calendar failure, the other is just more work done.
Both at once
Overdue wins the border, over-target keeps the bar. Two badge lines stack; the row grows.
Completed over
Strikethrough title, overflow-tinted final duration, no pulse.
Reboot & clock edge cases
Resumed task
After an offline gap over 1 min, active rows carry a one-launch resumed · +2h 14m offline line in textDim. Dismissed on any interaction; never persisted.
Corrupt save
status = active with no active_since: fall back to app_state.last_saved_at and show estimated beside the duration.
Clock moved back
A negative now − active_since clamps to zero rather than showing a negative duration; the row shows — until the next tick is positive.
Implausible gap
Over 24 h offline: the duration is shown but flagged, with a Trim to 24 h action in the row menu. Nothing is silently discarded.
Unclean exit
Startup runs PRAGMA integrity_check and, on failure, opens Settings → Data with the result rather than starting normally.
QML / C++ notes
Send notifications over org.freedesktop.Notifications with QtDBus directly — QSystemTrayIcon::showMessage gives no actions and no icon control. Fail silently when the service is absent; never fall back to an in-app modal, which would steal focus from whatever the user is actually doing.

Reuse one notification id per task so a re-fired warning replaces rather than stacks.

All comparisons in QDateTime::currentDateTimeUtc(); format only at the display boundary. The Future→Pending promotion, the 1-hour deadline warning and the now line all share a single 60 s timer so they can never disagree about the current minute.

Conflicts & scope
Media keys are declared with StandardKey and are frequently grabbed by the compositor before Qt sees them; the Alt+[ / ] pair is the documented fallback, not an alias.

Space is window-scoped and suppressed whenever a text field has focus — otherwise typing a task title starts the timer.

No global (system-wide) hotkeys in v1: registering them portably across X11 and Wayland needs a portal and is out of scope.
Discoverability
Every shortcut appears in the tooltip of the control it drives, and the full list lives in Settings → a Shortcuts pane rendered from the same table that generates the Shortcut objects — so the documentation cannot drift from the bindings.

Two clocks, never merged
Active duration = self_elapsed_ms + (now − active_since) — wall-clock, and it keeps running through a shutdown because active_since predates the reboot.

Logged work = Σ sessions.duration_ms — only time the timer was actually running, credited to every active task on phase complete.

targetProgressBasis decides which of the two drives progress bars. Every bar in the UI uses the same basis; mixing them per-view would make two screens disagree about the same task.
Durability
WAL journal, foreign_keys=ON, synchronous=NORMAL. Immediate write on every lifecycle change; a 10 s heartbeat while anything is active; a logind PrepareForShutdown hook that commits and runs wal_checkpoint(FULL) before power-off. Worst case on a hard power loss is 10 s of lost wall-clock.
